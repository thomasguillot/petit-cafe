# Agent Guide: Petit Café

This file is the authoritative agent/AI guide for this repo. CLAUDE.md imports it via `@AGENTS.md`.

## What this project is

A native macOS menu-bar app that keeps the Mac awake for a chosen duration.
Targets macOS 26 (Tahoe)+ on Apple silicon only (`ARCHS: arm64`; there is no Intel build, on
purpose). Unsigned: no Apple Developer Program, no signing, no notarization.
MIT licensed. The whole app is one menu plus a small About window: no main window, no settings
window, and two options (Launch at Login in the menu, automatic update checks in About).
The concept is a petit café: simple, no faff. It is `caffeinate` from the menu bar.

## Build and test commands

### PetitCafeKit (pure Swift, no Xcode needed)

```sh
cd PetitCafeKit && swift test
```

### App

After any change to `App/project.yml` or adding/removing source files, regenerate first:

```sh
cd App && xcodegen
```

Build (headless):

```sh
cd App && xcodebuild \
  -project PetitCafe.xcodeproj \
  -scheme PetitCafe \
  -destination 'platform=macOS' \
  build
```

### Release DMG

```sh
./scripts/make-dmg.sh
```

Writes `dist/Petit-Cafe-<version>.dmg`. The version comes from `MARKETING_VERSION` in `App/project.yml`.

### SwiftLint: MUST run from repo root

```sh
swiftlint lint --quiet
```

### App icon

Every icon comes from one glyph, `App/Icon/petit-cafe-glyph.svg` (two paths with the ids
`cup` and `steam`). Edit it, then run `swift scripts/make-icon.swift`. It regenerates:

- `AppIcon.appiconset`: the steaming cup in ivory on the green rounded rect (same full-bleed shape
  and 0.224 corner radius as Hosts Switchr and Natalie).
- `MenuBarIconOn.imageset` and `MenuBarIconOff.imageset`: template images, with and without steam.
- `site/assets/icon.png`.

The glyph is our own copy, not a dependency. Keep its path commands absolute (M, L, H, V, C, Z);
that is all the script parses. The menu-bar replica in `site/index.html` inlines the same paths,
so update it by hand when the glyph changes.

## How the app works

- `Cafe` (PetitCafeKit) is the carte: Expresso (15 minutes), Noisette (30 minutes), Allongé
  (1 hour), Double (2 hours), Grand crème (5 hours), À volonté (indefinitely).
- `AwakeSession` owns all state: the active café and its end date. It is `@MainActor` and
  reports changes through `onChange`.
- `SleepPreventing` is the seam over IOKit power assertions. `IOKitSleepPreventer` is the real
  one (it holds `PreventUserIdleDisplaySleep`); tests use a fake.
- A timed café schedules its own expiry on the continuous clock, so time spent asleep
  (lid closed) still counts.
- The menu bar cup shows its steam while a café is active and loses it when the Mac can sleep.
- A right-click (or Control-click) on the cup is a shortcut: it serves À volonté when nothing is
  active and switches off whatever is active otherwise. For that to work the menu is not assigned
  to the status item; a left click assigns it, opens it, and removes it again.
- Every change of café posts a native notification (`CafeNotifier`, UserNotifications), with the
  wording built by `CafeNotice` in the Kit. Permission is requested lazily on the first change.
  Each notice clears the previously delivered ones and is posted under a fresh identifier, so
  there is always a new banner and never a pile. If the user dismisses the permission banner
  without choosing Allow, macOS records a denial and the app cannot ask again.
- Updates are the Hosts Switchr updater, ported file for file: `ReleaseFetcher` reads GitHub
  Releases for `thomasguillot/petit-cafe`, `UpdateAvailability`/`UpdatePlan` (Kit) decide what is
  installable, `UpdateController` drives `UpdateWindow`, `UpdateDownloader` streams the DMG with
  https, size and content-type guards, and `UpdateInstaller` swaps `/Applications/Petit Café.app`
  and relaunches. `UpdateScheduler` runs one background check 10 minutes after launch when
  `autoCheckForUpdates` is on. The About window (`AboutWindow.swift`) has the manual check and
  that checkbox. Keep the two projects' updaters in step when fixing either.
- An update keeps the café that was active. Just before the relaunch the app records the café
  and its end date in `UserDefaults` (`CafeHandover`, Kit), and the new copy takes it on launch
  and calls `AwakeSession.resume`, with no notification. A timed café keeps its original end
  time. The record is only honored for five minutes, so a relaunch that never happened cannot
  switch a café on later. An ordinary quit still ends the café.
- The DMG must keep `Petit Café.app` at its root under that exact name, or the installer
  reports a missing app.
- The updater has diverged from Hosts Switchr in these ways, all of which Hosts Switchr would
  benefit from too: the installer checks the mounted app's bundle identifier and version, stages
  the copy in /Applications and swaps it in rather than deleting first; a published `sha256`
  asset digest is verified after download; fetch and download errors are `LocalizedError`s;
  `checkNow` cannot interrupt a check, download or pending install; each download task only
  sets state while it still owns the download; the About button always re-checks; and the
  check alerts are handed to the run loop so they do not hold up the main actor.
- The "Update to …" row is the one accepted exception to the fixed menu size: it adds a row when
  an update has been found.
- The app target is an `NSStatusItem` with an `NSMenu` rebuilt in `menuNeedsUpdate`. Each café
  is a menu item with its duration as an `NSMenuItemBadge`; ordering the active café again
  switches it off.
- The menu must never change size or shift between states. Two things keep it still: its
  `minimumWidth` is pinned at launch to the widest status line, and every tickable item carries
  an empty `offStateImage` so the tick column is reserved before anything is ticked.
- Launch at Login is a menu item backed by `SMAppService.mainApp` (`SMAppServiceLoginItem`),
  behind the `LoginItemControlling` seam in the Kit. It works unsigned.
- It is on by default: `LaunchAtLogin.enableByDefault` registers the login item once, on the first
  run from an Applications folder, and records that in `UserDefaults` so a user who turns it off
  is never overridden. Copies run from elsewhere (the DMG, the build folder) are left alone.

## The site

`site/index.html` is a single static page with all CSS and JS inline. It is published to
Spacefast (the Space ID is in `.spacefast/space.json`). The download button resolves the latest
DMG from the GitHub Releases API at runtime. Design context lives in `docs/PRODUCT.md` and
`docs/DESIGN.md`.

The site tracks nothing. The fonts (EB Garamond, Fraunces Black) are self-hosted in
`site/assets/fonts/` as latin-subset WOFF2 files, with their OFL licenses alongside. The GitHub
Releases API call is the only request the page makes to another host.

## Branches

`main` is protected: every change goes through a pull request. Work on a branch and open a PR.

## What NOT to do

- Do not add signing, notarization, or helper daemons.
- Do not give the executable an accented name: `EXECUTABLE_NAME` stays `PetitCafe`, or codesign
  rejects the bundle. Only the bundle and display name carry the accent.
- Do not add a main window, a settings window, or further options (display toggles, custom
  durations). The carte, Launch at Login and the About window are the whole app.
- Do not add analytics, trackers, or fonts, scripts and styles loaded from another host to the site.
- Do not push to `main` directly.
- Do not commit anything under `docs/`.
- Do not add `Co-Authored-By` to commits.
